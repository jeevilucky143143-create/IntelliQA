Dialogue Frame Architecture

IntelliQA maintains conversational context using a lightweight ConversationFrame structure stored within Flask sessions. This allows coreference resolution across multiple turns without needing complex LLMs.

Multi-Turn Dialogue Execution Pipeline

1
USER QUERY "Who created Python?" / "Who created it?"
2
QUERY ROUTER Detect intent: Greeting, KB, Dialogue Follow-up, or IR
3
CONTEXT RESOLUTION Substitute pronouns ("it" → "Python") using Session Frame
4
QA ENGINE EXECUTION Execute Knowledge Query / IR Passage Search
5
FRAME CONTEXT UPDATE Store active entity ("Python"), question, and answer in Session

ConversationFrame Data Schema

class ConversationFrame:
    intent: str            # e.g. 'KNOWLEDGE', 'IR', 'GREETING'
    entity: str            # Active entity (e.g. 'Python')
    attribute: str         # Active attribute (e.g. 'creator')
    previous_entity: str   # Entity from turn t-1
    previous_question: str # User query from turn t-1
    previous_answer: str   # Bot answer from turn t-1
    context: dict          # Additional metadata
    timestamp: float       # Epoch timestamp
    history: list          # Full session turn history

Example Dialogue Resolution

User: "What is Python?" Bot: "Python is a high-level programming language..." → Frame Entity set to "Python"
User: "Who created it?" Bot: "Python was created by Guido van Rossum." → Coreference resolved: "it" → "Python"
